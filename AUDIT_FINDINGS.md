## How to use

1. Extract `cleanup_project.sh` and `restore_cleanup.sh` into your project root: `~/hackathons/changeimpactbench-v0.2/`.
2. Review candidates: `bash cleanup_project.sh` (default safe-profile dry run).
3. Move only regenerable items: `bash cleanup_project.sh --apply --profile safe`.
4. Optional old UI docs: `bash cleanup_project.sh --apply --profile docs`.
5. Optional derived summaries: `bash cleanup_project.sh --apply --profile summaries`.
6. **Not recommended:** `bash cleanup_project.sh --apply --profile legacy-tests --confirm-coverage-loss`.
7. To reverse any operation, copy the absolute `Backup:` path printed by the script and run: `bash restore_cleanup.sh '/absolute/path/to/.cib-cleanup-...'`.
8. Re-run checks: `source .venv/bin/activate && bash scripts/check_release.sh`.

The cleanup backup is created in the parent of the project, not inside it, to avoid accidental inclusion in the final submission ZIP. Do **not** upload the backup directory publicly: it can include original research records or notes. The `safe` profile will be partially recreated after the release audit runs; that is expected.

## Scope and limitations

This is a dependency/use-based file audit, not a full security penetration test or a validation of all live-model benchmark outcomes. We did not modify task versions or score historical runs. A real OpenRouter run, human semantic review of AG09–AG12 and a dependency-backed Next.js production build remain separate verification work.
