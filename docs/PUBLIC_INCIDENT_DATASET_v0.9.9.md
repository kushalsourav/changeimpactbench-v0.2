# Public-incident grounding and reconstructed evaluation (v0.9.9)

The **historical incidents are real**. The benchmark environment is a simplified **deterministic reconstruction** authored from public operator postmortems. No operator has provided production logs, a full service topology, internal configuration dumps, cost estimates, or ground-truth counterfactual repair outcomes. These modeled elements MUST NOT be represented as recorded incident facts.

## Protocol and limitations

- Task source provenance is preserved in `tasks/RW*.json` and `benchmarks/public_sources.json`, with a separate field for documented facts versus assumptions.
- Only the alert, neutral hypotheses and initial service inventory are presented in the agent's initial prompt. The operator postmortem and reference repair selection remain on the reviewer side; source facts must not leak the answer in the agent prompt.
- The agent can investigate only the locally implemented tools. Metrics/log responses are **generated by the sandbox**, not fetched from GitHub or Cloudflare infrastructure. Repair actions cannot affect real systems.
- `oracle.py` computes reference outcomes for the reconstruction. A strict pass is therefore **correctness against the modeled benchmark**, not proof the model could repair the actual historical outage.
- Models and trials are recorded independently. A comparison must use identical frozen task versions and settings. API failures and tool-budget exhaustion are non-gradeable, not silently scored as wrong answers.
- The optional LLM synthesis analyzes regraded records separately. The summarizing model can choose an appropriate chart and author interpretations, but its chart values are computed from independent deterministic replay; its claims must be separately human reviewed. Its model and output are hash-bound to the selected result file.
- A user must explicitly approve each batch's potential provider requests (`48 × models × trials`) and separately approve one synthesis request. Provider-specific rate limits may preclude large batches.

## Why three tasks instead of five

Only three postmortems have been explicitly source-checked and reconstructed in this release. The five earlier AG08–AG12 synthetic tasks are not active or included. More real-world incidents should be added only after validating source fidelity, oracle alignment and evidence discoverability; the benchmark version must change when cases/tools change.

## Interpreting the sources

These pages are primary operators' retrospective reports, not exported raw logs. The benchmark records **model-generated investigation tool calls**, simulator observations, and independent grades. Human reviewers should check source-to-mechanism mapping and each important generated interpretation before a scientific claim is made.
